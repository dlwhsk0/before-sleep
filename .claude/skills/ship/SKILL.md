# ship — 검증하고 커밋·푸시하기

이 프로젝트의 "코드 → 검증 → 커밋" 리듬을 그대로 실행하는 절차다.
**검증이 통과하기 전에는 절대 커밋하지 않는다.**

## 절차

1. **테스트**: `npm run test` — 실패하면 멈추고 원인부터 고친다.
2. **빌드/타입체크**: `npm run build` — 타입 에러나 빌드 실패면 멈추고 고친다.
   (Node 버전 경고 `You are using Node.js ...`는 무시해도 된다.)
3. **UI 변경이면** dev/preview로 최소 확인(HTTP 200, 콘솔 에러 없음):
   - `npm run dev` 또는 `npm run preview` 후 절대경로 도구(`/usr/bin/curl`, `/usr/sbin/lsof`)로 확인하고 서버를 정리한다.
4. **문서**: 빌드 단계가 완료됐으면 `CLAUDE.md`의 "빌드 단계" 체크리스트와
   바뀐 데이터 모델/컨벤션을 갱신한다.
5. **커밋**: 현재 브랜치가 `main`인지 확인하고, 의미 있는 한국어 메시지로 커밋한다.
   메시지 마지막 줄에 반드시 아래 trailer를 넣는다:

   ```
   Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>
   ```

6. **푸시**: `git push origin main`.
7. **보고**: 커밋 해시와 한 줄 요약을 사용자에게 알린다.

## 규칙

- 사용자가 명시적으로 요청할 때만 이 스킬을 실행한다(커밋/푸시는 사용자 승인 행위).
- 여러 개의 자잘한 시각 조정은 한 논리 단위로 묶어 한 번에 커밋한다.
- `git push`는 외부로 나가는 작업이므로, 되돌리기 어려운 상황이면 먼저 확인한다.
- 커밋 작성자 신원은 저장소 설정(`dlwhsk0 <hana.dev.314@gmail.com>`)을 그대로 쓴다.
